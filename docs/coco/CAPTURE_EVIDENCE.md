# COCO 采集验证记录模板

本文只保留可重复使用的记录结构。真实文件名、时间、设备标识、帧内容、摘要和单次分析结论保存在本机采集目录，不写入项目说明。

Apple 平台上的通用采集步骤见 [iPhone 蓝牙数据采集](../apple/IPHONE_BLUETOOTH_CAPTURE.md)。本文只记录 COCO 对采集证据的设备专属要求。

## 输入保全

对每份输入在本机记录：

| 字段 | 内容 |
| --- | --- |
| 操作摘要 | 原控制端执行的单一动作 |
| 触发时间 | 完成动作并触发诊断的本地时间 |
| 原始归档摘要 | 原始诊断归档的 SHA-256 |
| 蓝牙日志摘要 | 提取出的 PacketLogger 文件 SHA-256 |
| 备注 | 是否包含连续日志、重复动作或其他干扰 |

任何提取和裁剪都基于保全后的原件副本进行。

## 传输通道确认

从服务发现和写入记录中确认：

- 目标主服务与写入特征；
- 写入能力和实际 ATT 写入方式；
- 通知特征及是否成功订阅；
- 协商 MTU；
- 停止指令及其重复出现情况。

确认后的运行配置写入 COCO 设备画像，说明文档只保留验证方法。

## 候选区间记录

每个候选区间至少记录：

- 起始和结束源帧；
- 相对起始时间与总时长；
- 写入总数；
- 最终停止帧是否完整；
- 区间内是否出现中间停止后继续运行；
- 规范化日程 SHA-256。

若同一日志包含多次操作，应按时间和帧号拆分，避免把相邻动作合并成一个频率。

## 采用条件

- 起点对应目标动作的首次有效写入；
- 终点对应目标动作的最终停止；
- 中间时序连续且与原控制端表现一致；
- 规范化摘要可重复计算；
- 短运行、完整运行和提前停止均通过真机验证。

## 实现对应关系

- 设备画像与协议：`miniprogram/devices/coco/`
- 内置频率：`miniprogram/devices/coco/frequencies/`
- 频率格式与完整性校验：`miniprogram/utils/frequency-schema.js`
- 调度与取消：`miniprogram/utils/program-runner.js`
- 抓包转频率工具：`tools/coco/extract-frequency.py`
- 核心回归测试：`tests/run-tests.js`

原始诊断归档、实际证据表和中间分析结果只留在被 Git 排除的本机目录中。
