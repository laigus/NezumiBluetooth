# 可扩展 BLE 控制器架构

## 设计原则

1. BLE 基础能力与具体设备协议分离。
2. 每种设备通过独立模块提供识别、传输、协议和页面。
3. 功能是可选能力，不要求所有设备采用同一种数据或交互模型。
4. 设备专属源码、文档和本地工具使用相同的设备目录名归档。
5. 高级调试始终保留原始 GATT 入口，用于分析尚未正式接入的设备。

## 代码分层

| 层 | 路径 | 职责 |
| --- | --- | --- |
| 应用入口 | `miniprogram/app.js` | 初始化 BLE 与设备会话，处理前后台生命周期 |
| BLE 核心 | `miniprogram/core/bluetooth.js` | 扫描、连接、GATT 发现、读写、通知、分包和日志 |
| 设备会话 | `miniprogram/core/device-session.js` | 管理当前设备定义、画像、控制器和连接模式 |
| 设备注册表 | `miniprogram/devices/index.js` | 校验并注册设备模块，匹配广播和汇总扫描条件 |
| 设备模块 | `miniprogram/devices/<device>/` | 保存该设备的识别、画像、协议、页面入口和专属数据 |
| 页面 | `miniprogram/pages/` | 设备管理、高级调试，以及设备模块声明的共享或专属页面 |
| 共享逻辑 | `miniprogram/utils/` | 仅保存可被页面或多个模块复用的运行逻辑 |
| 设备工具 | `tools/<device>/` | 对应设备自己的本地采集、转换或辅助工具 |
| 测试 | `tests/run-tests.js` | BLE 核心、注册表和已注册设备模块的稳定契约 |

`core/` 不导入 `devices/` 中的具体模块。协议命令、握手、通知解释和设备动作只能由设备控制器或设备专属功能处理。

## 设备模块契约

每个 `miniprogram/devices/<device>/` 至少包含：

- `definition.js`：模块 ID、广播匹配、扫描条件、页面入口、能力声明和控制器工厂；
- `profile.js`：服务、特征、MTU、分包与写入方式等传输配置；
- `controller.js`：把原始 BLE 读写包装成该设备的协议动作。

模块可按需增加：

- 专属页面；
- 内置数据目录；
- 数据编码与解析文件；
- 本机存储命名；
- 仅服务该设备的其他实现。

这些可选内容没有统一的数据形状。注册表只汇总模块明确声明的能力，不应因为已有模块使用某项功能，就要求后续模块也实现它。

## 设备管理连接流

1. 注册表汇总所有模块声明的扫描条件并交给 BLE 核心。
2. 广播发现后，各模块通过 `matchAdvertisement()` 独立评分。
3. 设备管理从匹配结果中选择目标，并把对应画像注入设备会话。
4. BLE 核心完成连接、MTU、服务与特征发现。
5. 设备会话创建协议控制器并执行初始化与兼容性确认。
6. 连接可用后，设备管理显示当前设备；点击设备进入模块声明的控制页面。
7. 主动断开会暂停自动重连，直到用户再次点击“扫描并连接”。

## 页面隔离

- `app.json` 必须静态登记所有可能跳转的页面路径。
- 功能相同的模块可以复用页面，功能不同的模块应提供自己的页面。
- 页面从当前设备会话取得定义和控制器，不直接猜测设备类型。
- 设备专属文案、按钮和数据只出现在对应页面或设备文档中。

## 高级调试

- 进入页面只初始化蓝牙适配器，不自动扫描。
- 用户点击“开始扫描”后才发现全部附近 BLE 设备。
- 已识别设备可以注入对应画像；未知设备使用通用 GATT 探查与收发流程。
- 停止扫描、离开页面或重新进入后都保持停止状态。

高级调试用于发现新设备的广播、服务、特征和原始数据；确认协议后，再把稳定逻辑迁入新的设备模块。

高级调试复制出的设备画像、设备 ID、广播数据、时间和收发日志属于本机诊断信息，只用于当前分析，不进入公开仓库。

## 本地工具边界

- 每个设备的工具只放在 `tools/<device>/`。
- 不建立跨设备工具注册表或统一命令入口。
- 工具名称、输入、输出和处理方式由对应设备决定。
- 不需要本地工具的设备不创建工具目录。
- 原始采集和中间分析仍放在 Git 排除的本机目录中。

## 接入新设备

1. 先在高级调试中确认广播识别、GATT 通道和基础收发。
2. 创建 `miniprogram/devices/<device>/`。
3. 实现定义、画像和协议控制器。
4. 选择共享页面或增加专属页面，并登记到 `app.json`。
5. 在 `miniprogram/devices/index.js` 增加一条静态注册。
6. 只为该设备确实拥有的能力增加数据、页面和工具。
7. 为稳定的识别、连接与核心协议行为增加最小回归测试。
8. 用真机检查连接、操作、断开和重新进入流程。

已有设备的内部实现与使用说明放在对应设备文档目录；当前可从 [COCO 文档](coco/README.md) 进入。
